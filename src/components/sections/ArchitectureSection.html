Architecture

One multi-agent architecture shared by six products

We don't hide intelligence inside a single prompt. Understanding the business and producing side effects on real systems are governed separately: the semantics & knowledge layer understands, the capability layer produces, the execution layer acts safely, and the entry layer puts it in people's hands.

Agent Team: dispatcher + executors + reviewer

Complex tasks are completed by an Agent Team: the lead agent decomposes the goal, sub-agents own their parts, and Steward manages the whole lifecycle conversationally. Teams have input definitions, environment and connector configuration, sharing and permission grants, and step-level traceable run records.

  • Lead / sub-agent division of labour and escalation
  • Shared memory, sessions and artifacts
  • Human in the loop: one-off approval · session approval · remembered grants · reject · timeout
  • Task diagnostics and failure attribution

MCP: enterprise systems become tools agents can discover and call

Ontology, Knowledge Fabric, Connector and the tool gateway all expose capabilities over MCP: agents discover tools, read business context and execute controlled actions through a standard interface. OAuth, health checks and a tool registry keep every connection manageable and auditable.

  • Ontology / knowledge base queries over MCP
  • OpenAPI / Swagger converted into AI tools in one step
  • MCP OAuth · least-privilege tokens · regular rotation
  • Built-in / public / private MCP connections

A2A: standard collaboration between agents

Agent Factory offers A2A and OpenAI-compatible endpoints; ITEMGPT and PA can discover and delegate to external expert agents; Knowledge Fabric can be queried by external agents over A2A. Cross-product, cross-tenant and cross-vendor agent collaboration runs on one protocol.

  • Agent discovery, delegation and callbacks
  • OpenAI-compatible API · drops into existing apps
  • Idempotent requests, session reuse, access audit
  • External grants and API key management

Model gateway · Tool gateway · Connector · VFS

The model gateway unifies providers and protocols, attributes usage and cost by app / tenant / user / agent, and enforces quotas and failover. Connector centrally manages external system connections, credentials (AES-256-GCM with tenant-derived keys), triggers and message channels. VFS gives agents a cloud file system with memory projections.

  • Hybrid routing: leading US models + Chinese open-source / on-prem models
  • Connectors for Bitbucket · Confluence · Jira · SharePoint · Figma · 3CX · MySQL · PostgreSQL and more
  • Channel adapters for Teams · Slack · Telegram · Feishu · DingTalk · WeCom
  • S3 / PostgreSQL / Redis three-tier storage · L0/L1/L2 summary retrieval
